# V0.2 可恢复任务运行时验收记录

## 结论

V0.2 于 2026-09-11 完成。WellPhone 已将模型接入、权威对话历史、Tool Result 续接、请求幂等租约和任务检查点迁移到 Python/PostgreSQL 服务端；iOS 客户端保留用户确认、系统权限、EventKit 写入、设备凭证和真实结果验证。

下一阶段是 V0.3 多模态输入，不再属于运行时迁移。上下文管理优化和长期记忆按产品决定留到独立阶段，不在本次验收范围内。

## 已验收能力

- 聊天请求使用稳定 request ID；断流或重试不会重复调用模型或生成第二张任务卡片。
- PostgreSQL 保存权威对话历史、Provider Tool Call 上下文、Tool Result、续接租约和任务检查点。
- 客户端在每个关键状态转换前后持久化单调 revision，服务端拒绝冲突 revision 和非法 status/phase 组合。
- 等待确认的任务在 App 重启后保持等待状态，不执行系统写入。
- 已取得 execution receipt 的任务只恢复验证；没有 receipt 时先按 Tool 幂等标记恢复真实结果。
- 瞬时错误重试次数和退避时间可恢复；非幂等或结果不确定的操作不会盲目重放。
- 运行中取消和执行 Deadline 都遵循“先确认真实写入结果，再决定终态”的规则。
- 同一任务的并发恢复调用在客户端合并，避免重复恢复或重复验证。

## 测试环境说明

本轮自动 UI Runner 在真机上两次均于断言开始前被 Xcode 的 DTX 连接拒绝；模拟器重试又因本机 Xcode 缺少可用调试器版本而无法启动 Runner。两类错误均发生在测试基础设施启动阶段，没有产生 WellPhone UI 断言失败。核心恢复逻辑已由真机上的 32 个自动化测试覆盖，App 冷启动和人工流程另行验证；修复 Xcode Runner 环境后仍应补跑 UI 套件，但这不改变 V0.2 运行时迁移的验收结论。
